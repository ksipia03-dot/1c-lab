# Firewall Timeweb Cloud — сервер 1C-Lab (Brave Smew)

> **Когда читать:** RDP/SSH не подключаются, в панели Timeweb режим **«Разрешить трафик»** и **ноль входящих правил** — или сервер подключён к такой группе без правил.
>
> **Сервер:** `201.34.129.230` · **Имя:** Brave Smew · **serviceId:** `8869583` · **ОС:** Windows Server 2022

---

## Почему «пустой белый список» = ничего не работает

Timeweb Cloud Firewall (FWaaS) работает **до** Windows — на уровне облачной сети. Группа типа **«Разрешить трафик»** (whitelist) пропускает **только** трафик, явно описанный во входящих правилах. Всё остальное **отбрасывается**.

| Ситуация | Что происходит |
|----------|----------------|
| Сервер **не** подключён ни к одной группе правил | Файрвол не действует, весь трафик разрешён |
| Группа **«Разрешить трафик»**, сервер подключён, **0 входящих правил** | **Весь входящий трафик заблокирован** (RDP, SSH, WinRM, ping) |
| Группа **«Разрешить трафик»**, есть правила только на вход | Исходящий трафик **не фильтруется** (если нет исходящих правил) |
| Группа **«Разрешить трафик»**, добавлено **хотя бы одно исходящее** правило | Фильтруется и исходящий: всё, что не разрешено явно, **блокируется** |

Симптом на Mac совпадает с блокировкой на perimeter: TCP-handshake иногда проходит, но **нет ответа протокола** — RDP обрывается с *«Your session ended because of an error»*, SSH висит на timeout, WinRM/HTTP не отвечают.

> **Важно:** Windows Firewall на сервере настраивается **после** первого успешного доступа скриптом `setup-server.ps1`.
>
> **Статус (2026-08):** облачный firewall Timeweb настроен — **TCP 3389 (RDP) работает**. Если RDP всё ещё обрывается с *«Your session ended because of an error»*, причина обычно **не** в firewall, а в **alternate shell** в `.rdp`-файле — подключайтесь через **`ERP-Uchebny-plain.rdp`** или **`ERP-Uchebny.rdp`** *(plain, без alternate shell)*.

## Окно «Добавить правило» (как в UI)

В блоке **«Входящий трафик»** нажмите **«Добавить правило»**. В модальном окне:

| Поле в UI | Что выбрать |
|-----------|-------------|
| Переключатель адреса | **Для всех адресов** *(вместо «Для подсети»)* |
| **Тип** | Пресет из списка **или** **Своё правило** |
| **Протокол** | Появляется только для **Своё правило**: TCP, UDP, ICMP, TCP6, UDP6, ICMP6 |
| **Порт** | Появляется только для **Своё правило** |
| Комментарий / описание | Произвольный текст для себя (например `RDP`) |

**Список пресетов в поле «Тип»** (поиск по выпадающему списку):

ALL TCP · ALL UDP · DNS TCP · DNS UDP · HTTP · HTTPS · ICMP · Kafka · MongoDB · MySQL · OpenSearch · Clickhouse · PostgreSQL · RabbitMQ · Valkey (Redis) · SMTP · **SSH** · **Своё правило**

> **RDP и WinRM в пресетах обычно отсутствуют** — их нужно создавать через **Своё правило**. Если нужного пресета нет в видимой части списка, прокрутите список или сразу выберите **Своё правило** и укажите протокол и порт вручную.

**Безопаснее «Для всех адресов»:** переключите на **Для подсети** и укажите **ваш текущий публичный IP** с маской `/32`, например `203.0.113.45/32`. Узнать IP на Mac: [ifconfig.me](https://ifconfig.me) или `curl -4 ifconfig.me`. При смене сети правило нужно обновить.

## Таблица входящих правил (скопируйте в UI)

Добавьте **каждую строку** отдельным правилом в блоке **«Входящий трафик»**.

### Фаза 1 — обязательно (bootstrap и RDP)

| № | Комментарий | Адрес | Тип | Протокол | Порт | Обязательно |
|---|-------------|-------|-----|----------|------|-------------|
| 1 | RDP | Для всех адресов | **Своё правило** | TCP | **3389** | **Да** |
| 2 | SSH | Для всех адресов | **SSH** *(пресет, порт 22)* | — | — | **Да** |
| 3 | WinRM HTTP *(опционально)* | Для всех адресов | **Своё правило** | TCP | **5985** | По желанию |

**Альтернатива для SSH:** если пресет **SSH** недоступен — **Своё правило**, протокол **TCP**, порт **22**.

> **SSH с «Для всех адресов»:** удобно для CI/агента, но порт 22 виден в интернете. После bootstrap рекомендуется сузить источник до вашего IP или отключить парольный вход в OpenSSH (ключ уже прописывает `setup-server.ps1`).

### Фаза 2 — только когда понадобится тонкий клиент 1С с других машин

| № | Комментарий | Адрес | Тип | Протокол | Порт | Когда |
|---|-------------|-------|-----|----------|------|-------|
| 4 | Агент сервера 1С (ragent) | Для всех адресов | **Своё правило** | TCP | `1540-1541` | Тонкий клиент **не** с этого сервера |
| 5 | Рабочие процессы 1С | Для всех адресов | **Своё правило** | TCP | `1560-1591` | То же |

Для учебного стенда с RDP + thick client **на самом сервере** фазу 2 можно **не открывать**.

### Явно НЕ открывать

| Порт | Сервис | Почему |
|------|--------|--------|
| **8080** | MCP HTTP (1С) | Доступ только с **localhost** на сервере; наружу не публикуется |
| 5986 | WinRM HTTPS | Не требуется для текущего сценария |
| 445 | SMB | Не нужен для bootstrap |

## Подключение группы к серверу

### Вариант A — отредактировать существующую группу

1. Войти в [Timeweb Cloud](https://timeweb.cloud/my) → **Сети** → **[Firewall](https://timeweb.cloud/my/firewalls)**.
2. Открыть группу, где режим **«Разрешить трафик»** и сервер **Brave Smew** уже подключён.
3. Добавить правила 1–2 по инструкциям выше *(и 3 при необходимости)*.
4. На вкладке **«Серверы»** / **«Сервисы»** убедиться, что в группе есть **Brave Smew** (`201.34.129.230`, serviceId `8869583`).
5. **Сохранить** изменения группы.

### Вариант B — создать группу с нуля

1. **Сети** → **Firewall** → **«Добавить»**.
2. Выбрать **«Разрешить трафик»**.
3. **«Добавить правило»** в **«Входящий трафик»** — внести правила 1–2 *(см. пошаговые блоки выше)*.
4. Блок **«Подключить к сервисам»** → **«Выбрать сервис»** → отметить **Brave Smew** (`201.34.129.230`).
5. Имя группы, например: `1c-lab-brave-smew`.
6. **Исходящий трафик** — **не заполнять**.
7. Нажать **«Создать»**.

### Альтернатива — со страницы сервера

1. **Облачные серверы** → **Brave Smew** → вкладка **«Сеть»**.
2. Блок **Firewall** → **«Настроить»**.
3. Выбрать существующую группу или **«Создать новый»** (далее как в варианте B).

## Исходящие правила

**Рекомендация для этого стенда: не добавляйте исходящих правил.**

Пока в группе **нет** исходящих правил, исходящий трафик с сервера **не фильтруется** — Windows сможет качать обновления, платформу 1С с [releases.1c.ru](https://releases.1c.ru), документацию с ИТС и т.д.

Если когда‑нибудь понадобится жёстко ограничить исходящий (корпоративная политика), минимальный набор — через **Своё правило**:

| Комментарий | Адрес | Тип | Протокол | Порт |
|-------------|-------|-----|----------|------|
| HTTPS — обновления, ИТС, релизы 1С | Для всех адресов | Своё правило | TCP | `443` |
| DNS | Для всех адресов | Своё правило | UDP | `53` |
| NTP *(опционально)* | Для всех адресов | Своё правило | UDP | `123` |

> Timeweb предупреждает: **одно** исходящее правило в режиме «Разрешить трафик» включает фильтрацию исходящего — всё неперечисленное будет **заблокировано**.

## Проверка после сохранения правил

Подождите **30–60 секунд** — правила применяются на edge без перезагрузки VM.

### 1. RDP с Mac

- Двойной клик по **`ERP-Uchebny-plain.rdp`** или **`ERP-Uchebny.rdp`** на рабочем столе *(plain, без alternate shell)* — или Microsoft Remote Desktop → `201.34.129.230`.
- Пользователь: **`Administrator`**, пароль — из ваших учётных данных *(не хранить в репозитории)*.
- Успех: полноценный рабочий стол Windows, без мгновенного обрыва сессии.
- **Не используйте** **`ERP-Uchebny-bootstrap.rdp`** для проверки firewall — это одноразовый bootstrap через alternate shell, только **после** успешного plain RDP.

### 2. Сообщите агенту в Cursor

Напишите, например: **«firewall настроен, продолжай bootstrap»**.

Агент запустит с Mac:

```bash
cd /Users/sergey/Documents/1С_тест
./scripts/server-access/remote-probe-and-bootstrap.sh
```

Скрипт дождётся SSH и выполнит на сервере `setup-server.ps1`: OpenSSH, каталоги `C:\1C-Lab\`, Windows Firewall (SSH снаружи, **MCP 8080 только localhost**), SSH-ключ Mac.

### 3. Проверка SSH *(после bootstrap)*

```bash
ssh -i ~/.ssh/id_ed25519_1clab Administrator@201.34.129.230 hostname
```

Ожидается имя хоста Windows без запроса пароля.

## Устранение неполадок

| Симптом | Что проверить |
|---------|----------------|
| RDP по-прежнему обрывается | Сначала **plain** `.rdp` *(без alternate shell)*; если plain работает — firewall OK. Иначе: правило **Своё правило → TCP → 3389**, адрес **Для всех адресов**, сервер в списке сервисов группы, прошла минута после сохранения |
| *«Your session ended because of an error»* сразу после входа | **Alternate shell** в `.rdp` — переключитесь на **`ERP-Uchebny-plain.rdp`** |
| SSH timeout | Пресет **SSH** или **Своё правило → TCP → 22**, служба `sshd` на сервере *(появится после bootstrap или userdata)* |
| Не нашёл RDP/WinRM в списке «Тип» | Это нормально — используйте **Своё правило** и укажите порт вручную |
| Сайты на сервере не открываются | В группе случайно добавлены **исходящие** правила — удалите их или добавьте `443/TCP` и `53/UDP` |
| Нужен только RDP с одного IP | Переключите **Для подсети** и укажите `ваш.IP.адрес/32` вместо **Для всех адресов** |
