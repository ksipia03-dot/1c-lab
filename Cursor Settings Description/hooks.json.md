# `hooks.json` — хуки на события редактора

## Назначение файла в системе

Файл регистрирует **хуки** — внешние команды (shell-скрипты), которые Cursor запускает автоматически при наступлении определённых событий жизненного цикла агента и редактора. Это штатная точка расширения: через хуки можно, например, авто-форматировать файлы после правок агента, отправлять уведомления, писать аудит-лог.

**Текущее состояние: хуков нет.** Зарегистрированы два события, но оба списка пустые — система полностью работает без хуков. Скилл `orchestration` упоминает «Hook auto-fixes formatting in background» на шаге Implementation — это отсылка к возможности, а не к настроенной функции: сейчас после правок worker'а никакой фоновой форматтер не запускается.

## Полный текст оригинала

```json
{
  "version": 1,
  "hooks": {
    "afterFileEdit": [],
    "subagentStop": []
  }
}
```

## Разбор полей

| Поле | Значение | Что означает |
|------|----------|--------------|
| `version` | `1` | Версия схемы файла хуков. Cursor по этому числу понимает, как парсить остальное содержимое. Самостоятельно менять не нужно — версию меняет сам Cursor, если формат хуков эволюционирует. |
| `hooks.afterFileEdit` | `[]` (пусто) | Событие «после правки файла агентом». Типичное применение — авто-форматирование (Prettier, Black, gofmt) или линт с авто-фиксом сразу после того, как агент изменил файл. Пустой массив = ни одна команда не привязана к событию = правки агента остаются ровно в том виде, в каком он их записал. |
| `hooks.subagentStop` | `[]` (пусто) | Событие «субагент завершил работу». Типичное применение — уведомления (звук, Slack, лог), сбор статистики по запускам субагентов. Пустой массив = остановка субагента ничего дополнительно не запускает. |

Каждое событие — это массив: хуков на одно событие может быть несколько, и они выполняются по очереди в порядке перечисления.

## ⚠️ Важно: как хуки получают данные (stdin, а не переменные окружения)

Command-хуки Cursor получают всю информацию о событии **как JSON-документ через stdin** (стандартный поток ввода), а **НЕ через переменные окружения**. Никакой переменной `$FILE` не существует — скрипт, который на неё рассчитывает, будет молча работать с пустым значением.

Поэтому правильный паттерн добавления хука — **вызов shell-скрипта, который читает stdin**. Удобно разбирать JSON через `jq`.

### Пример: авто-форматирование после правки

Шаг 1 — создать скрипт `.cursor/hooks/format.sh`:

```bash
#!/bin/bash
# Читаем JSON о событии из stdin
input=$(cat)

# Достаём путь к изменённому файлу
file_path=$(echo "$input" | jq -r '.file_path // empty')

# Если путь есть и файл с расширением .ts/.tsx — форматируем
if [ -n "$file_path" ]; then
  case "$file_path" in
    *.ts|*.tsx)
      npx prettier --write "$file_path" 2>/dev/null || true
      ;;
  esac
fi

exit 0
```

Шаг 2 — сделать скрипт исполняемым (`chmod +x .cursor/hooks/format.sh`) и зарегистрировать хук в `.cursor/hooks.json`:

```json
{
  "version": 1,
  "hooks": {
    "afterFileEdit": [
      { "command": ".cursor/hooks/format.sh" }
    ],
    "subagentStop": []
  }
}
```

Ключевые моменты примера:

- `input=$(cat)` — чтение всего stdin в переменную;
- `jq -r '.file_path // empty'` — извлечение поля из JSON-события (с защитой от отсутствия поля);
- `|| true` и `exit 0` — хук не должен «ронять» сессию агента, даже если форматирование не удалось;
- скрипт лежит в `.cursor/hooks/` рядом с `hooks.json` — так путь в `command` остаётся коротким и относительным.

### Что изменится, если добавить хук

| Действие | Эффект |
|----------|--------|
| Добавить хук в `afterFileEdit` | После **каждой** правки файла агентом будет запускаться указанная команда. Учтите стоимость: агент правит файлы часто, тяжёлый скрипт ощутимо замедлит работу. |
| Добавить хук в `subagentStop` | При завершении **каждого** субагента (worker, reviewer, …) будет запускаться команда. В оркестрации на 5 задач субагентов запускается десятки раз — хук сработает на каждом. |
| Оставить массивы пустыми | Текущее поведение: события происходят, но ни к чему не приводят. Нулевой оверхед. |

## Связи с другими файлами

- **Скилл `orchestration`** (`.cursor/skills/orchestration/SKILL.md`, описание — `skills/orchestration/SKILL.md` в этом справочнике): шаг Implementation упоминает фоновый хук авто-форматирования — как раз место, куда встал бы хук `afterFileEdit`. В заметках скилла также сказано, что воркфлоу «заменяет оркестрацию на базе хуков» — раньше такая автоматизация строилась через хуки, теперь через скилл.
- **Папка `.cursor/hooks/`** — условное место для самих скриптов хуков (пока не существует, т.к. хуков нет; появится при первом добавлении).
- **`config.json`** — не связан: хуки читают только `hooks.json`, проектный конфиг им не нужен.
- **Агенты и правила** — не читают `hooks.json`: хуки выполняет сам Cursor на уровне редактора, независимо от логики агентов.
